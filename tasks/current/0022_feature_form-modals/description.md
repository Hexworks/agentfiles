# Form modals

Builds the six `huh.Form`-backed modals listed in
`0015_task_refactor_ui/description.md`, section **Modals**. The generic
`modal.NewForm` adapter already exists in
`internal/tui/components/modal/form.go`; this task adds typed wrappers and
their result structs.

## Modals to ship

### 1. Create Profile Modal

Fields: `Name` (req), `Path` (req). Result: `CreateProfileInput{Name, Path}`.
On confirm, the screen calls the `CreateProfile` action.

### 2. Register Profile Modal

Field: `Path` (req). Result: `RegisterProfileInput{Path}`. On confirm, the
screen calls the `RegisterProfile` action.

### 3. Create Asset Modal

Fields (per parent description):
- `Name` (req)
- `Type` (req; one of `skill`/`agents_doc`/`settings`/`mcp`/`rule`/`hook`)
- `Description` (req)
- `Tags` (optional; csv)
- `CompatibleAgents` (optional; multi-select from
  `codex`/`claude-code`/`cursor`/`opencode`)
- `ExclusiveGroup` (optional)

Result: `asset.Manifest`. The asset `ID` is generated by slugifying `Name`
(reuse `slug()` in `internal/app/service.go`; export it or move to
`internal/utils`).

### 4. Edit Project Modal

Prefilled from an existing `*project.Manifest`. Fields:
- `Name` (req)
- `Path` (req)
- `EnabledAgents` (req; multi-select, at least one)

`Project.ID` is not editable; `SelectedAssetIDs` untouched. Result: modified
`*project.Manifest`.

### 5. Register Project Modal

Fields: `Name`, `Path`, `EnabledAgents` (all req). Result: new
`*project.Manifest` with `SelectedAssetIDs` empty (asset selection happens
later on the Select Project Assets Screen).

### 6. Create File Modal

Field: `Path` (req) — relative to the asset folder. Result: a typed
`CreateFileInput{Path}`.

## Layout

```
internal/tui/modals/
  create_profile.go
  register_profile.go
  create_asset.go
  edit_project.go
  register_project.go
  create_file.go
```

Each file exposes `New(...) *modal.Modal` plus the typed result struct.
`modal.NewForm`'s `extract` callback reads fields off the `*huh.Form` and
returns the typed result so `*huh.Form` does not leak out of the package.

## Tests

- For each modal: a unit test that builds the form, drives it via simulated
  `tea.KeyPressMsg` events, and asserts the `ResolvedMsg.Value` is the
  expected typed result with the entered fields.
- Edit Project Modal: prefill round-trip — building with an existing
  `*project.Manifest`, confirming without edits, the returned manifest
  equals the input (except for any normalization).
- Cancel via `<esc>` returns `ResolvedMsg{Confirmed: false, Value: nil}`.

## Out of scope

- The screens that open these modals (later tasks).
- Notifications Modal + Info Modal — those have non-form bodies (task 0023).
