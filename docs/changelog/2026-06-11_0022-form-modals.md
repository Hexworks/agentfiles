# 0022 changes

Added six `huh.Form`-backed modals under `internal/tui/modals/` plus their
typed result structs:

- Create Profile (`CreateProfileInput`)
- Register Profile (`RegisterProfileInput`)
- Create Asset (`asset.Manifest`)
- Edit Project (`*project.Manifest`)
- Register Project (`*project.Manifest`)
- Create File (`CreateFileInput`)

Each modal exposes a single `New(...) *modal.Modal` constructor and wires the
form through the existing `modal.NewForm` adapter so `*huh.Form` does not
leak. The `slug` helper used by the asset id derivation moved from
`internal/app/service.go` to `internal/utils/slug.go` as `utils.Slug` so the
modal package can reuse it without importing `internal/app`.

## Decisions

- **Per-modal `build<Modal>` helper + state pointer.** Each modal file
  pulls the form-construction logic into a private `build<Modal>(initial)
  (*huh.Form, *state)` returning the form together with the shared state
  pointer the field bindings write into. `New` wraps this into
  `modal.NewForm` with a small extract closure. — **Why:** keeps the
  public API a single `New(...)` while letting unit tests mutate state and
  assert the typed result without driving keypress-by-keypress submission
  through huh's unexported `nextField` / `nextGroup` message types.
- **Shared `AgentOptions()` and asset type options.** A single source of
  truth for the closed sets in `internal/tui/modals/agents.go` and
  `assetTypeOptions()` in `create_asset.go`. — **Why:** keeps the asset/
  project modals in sync with `asset.AllTypes()` and the agent ids the
  renderer accepts; avoids duplicating option lists across three modals.
- **Tags as a single comma-separated `Input`.** Bound to a string in
  `createAssetState`; parsed at extract time via `parseTags`. — **Why:**
  tags are an open-ended set, so `MultiSelect` does not apply; users
  already type them this way and it round-trips through `joinTags` for
  prefill.
- **Edit Project clones the existing manifest.** The extract closure
  returns a `*project.Manifest` cloned from the input, overlaying only the
  three editable fields. — **Why:** `Project.ID`, `SelectedAssetIDs`,
  `CreatedAt` are explicitly out of scope per the description; cloning
  also avoids mutating the caller's manifest in place if the modal is
  cancelled or replaced.
- **Register Project leaves `ID` empty.** The extract closure builds a
  `*project.Manifest` with `Name`, `Path`, `EnabledAgents` and an empty
  `SelectedAssetIDs`. — **Why:** the description says the screen calls
  `app.Service.AddProject`, which already runs `utils.Slug(name)` for the
  id and enforces ownership; duplicating slug logic in the modal would
  create two places to keep in sync.
- **Validators stay at the TUI input-shape layer.** `requiredString` and
  `requiredAgents` return a tiny sentinel error; domain validation (path
  safety, slug collisions, ownership) lives in `app.Service`. — **Why:**
  `docs/guidelines/tui.md` §"Keep Business Logic Behind Functions".

### Considered but rejected

- **Driving the test forms via real `tea.KeyPressMsg` events end-to-end.**
  Would match the description's wording most literally, but huh v2's
  `nextField` / `nextGroup` messages and `tea.Sequence`'s `sequenceMsg`
  type are unexported, which makes a faithful pump fragile and tied to
  internal huh details. Tests instead set `form.State` directly (same
  shortcut as `internal/tui/components/modal/form_test.go`), which still
  exercises the entire build → bind → extract → resolve path.
- **Reusing `slug` from `internal/app`** by exporting it in place.
  Would have left the modal package importing `internal/app`, reversing the
  TUI dependency direction. Moved to `internal/utils` instead.

## Assumptions

- **Asset id slugging is the modal's responsibility.** Description says
  "reuse `slug()` in `internal/app/service.go`; export it or move to
  `internal/utils`", so the modal sets `Manifest.ID = utils.Slug(Name)`
  before returning. Slug collisions still surface as `AssetExistsError`
  from `app.Service.InitAsset`, which the screen handles. — **Why:** the
  description's modal table explicitly lists "Result: `asset.Manifest`"
  with a slug-derived id.
- **Cancel-test coverage per modal is sufficient via the in-modal `New*`
  helper plus a direct `formContent.Lifecycle` test in
  `internal/tui/components/modal/form_test.go`.** Each modal's
  `*_test.go` adds a cancel test that aborts the form and asserts
  `ResolvedMsg{Confirmed: false, Value: nil}`. — **Why:** matches the
  description's explicit per-modal request.
- **The Register Project / Create Asset screens own the ID retry loop on
  slug collisions.** Modals just collect input; the screen plus
  `app.Service` already raise typed errors (`AssetExistsError`,
  ownership conflicts), and the screen re-opens the modal with the prior
  input pre-filled via the `initial` argument. — **Why:** the
  description explicitly puts retry behavior on the screen and refers to
  `app.Service` as the layer that enforces uniqueness.

## Other Notes

- The `huh` field builder requires `Value(*T)` to be called **before**
  `Options(...)` for both `Select` and `MultiSelect`. The first
  implementation chained them the other way around; the prefill case
  silently failed (the option's `selected` flag was never set because the
  accessor was still empty when `Options` ran). Fixed before the tests
  exposed it.
- No ADR / architecture / guideline updates were required: the task
  follows the patterns already documented in `docs/guidelines/tui.md`,
  `docs/guidelines/charm.md`, and `docs/guidelines/go.md`, and the parent
  UI design (`tasks/done/0015_task_refactor_ui`) already specifies the
  modal contracts.
- `internal/app/service.go` lost its private `slug` function and its
  single call site now uses `utils.Slug`. No public API change.

## Move `slug` to `internal/utils`

```go
// before — internal/app/service.go
func slug(v string) string { /* ... */ }
```

```go
// after — internal/utils/slug.go (exported so non-app callers can use it)
func Slug(v string) string { /* ... same body ... */ }
```

```go
// before — internal/app/service.go AddProject
manifest := &project.Manifest{
    ID:               slug(name),
    /* ... */
}
```

```go
// after — internal/app/service.go AddProject
manifest := &project.Manifest{
    ID:               utils.Slug(name),
    /* ... */
}
```

## New: `internal/tui/modals/`

```
internal/tui/modals/
  agents.go              # AgentOptions() + agent id constants
  validators.go          # requiredString / requiredAgents / parseTags / joinTags
  create_profile.go      # NewCreateProfile + CreateProfileInput
  register_profile.go    # NewRegisterProfile + RegisterProfileInput
  create_asset.go        # NewCreateAsset (returns asset.Manifest)
  edit_project.go        # NewEditProject (returns *project.Manifest, clones input)
  register_project.go    # NewRegisterProject + RegisterProjectInput
  create_file.go         # NewCreateFile + CreateFileInput
  *_test.go              # per-modal: confirm + cancel + stable-id tests
```

Each `New<Modal>` is a thin wrapper:

```go
func NewCreateProfile(initial CreateProfileInput) *modal.Modal {
    form, state := buildCreateProfile(initial)
    return modal.NewForm("create-profile", form, func(*huh.Form) any {
        return *state
    })
}
```

The `build<Modal>` helper holds the field wiring and the shared `state`
pointer; the `extract` closure reads from that same pointer, so `*huh.Form`
never leaves the package.
