# 0021 changes

Replaced the synchronous `huh` menu loop with the alt-screen Bubble
Tea shell described in task 0015. The new `internal/tui/shell`
package owns a screen-router stack (`PushScreenMsg` /
`PopScreenMsg`), intercepts the four global keys (`n`, `s`, `?`,
`q`) before the active screen sees them, mounts the
`notifications.Toast` widget above the status bar, and composes the
status bar from a fixed global set joined with each screen's
dynamic `StatusKeys()`. The shell ships a placeholder Welcome plus
stubs for the Notifications modal, Settings screen, and Info modal
so the global keys push something the user sees until tasks 0023
and 0024 land.

`cmd/af/main.go` was rewired to build `app.Service → actions.New →
notifications.NewLog → shell.New → tea.NewProgram`. The legacy
`tui.go` menu loop, `forms.go` flows, `render_preview.go`, and
`render_errors.go` were deleted; preview rendering returns inside
the project-detail screens in task 0027+, and error rendering now
flows through `notifications.From` (which carries `err.Severity()`
+ `err.Error()` into the toast already styled by
`notifications/render.go`).

## Decisions

- Use an interface-typed `Screen` and a heterogeneous stack rather
  than a closed view-enum on the root model — **Why:** the
  charm.md "concrete typed sub-models" pattern fits a fixed set of
  views, not the open-depth navigation stack the task requires. The
  patterns coexist: the stack handles navigation between entities;
  the state machine handles transitions inside a screen. Captured
  in ADR 0011.
- `Screen.Body(width, height int)` instead of `View() string` —
  **Why:** the shell controls layout (title bar, toast line, status
  bar). Handing each screen its content-area dimensions keeps
  layout policy in one place.
- Screens never mutate the stack directly; they emit
  `PushScreenMsg` / `PopScreenMsg` — **Why:** every stack change
  flows through the root, so push/pop is observable, testable, and
  consistently triggers the new screen's `Init()`.
- `q` quits everywhere, even on subscreens — **Why:** the task
  description specifies `q` as a global binding. Subscreens use
  `esc` to go back. The real Settings screen in 0024 may revisit
  this if needed.
- Toast.Update runs on the default branch (every non-handled
  message) instead of an explicit `case notifications.PushMsg,
  notifications.expireMsg` — **Why:** `expireMsg` is unexported in
  `internal/tui/notifications`, so the shell cannot name it in a
  type switch. The Toast harmlessly ignores everything except its
  own messages, so the default branch is correct and saves a type
  enumeration.

Considered but rejected:

- A single concrete view-enum (`viewProfile`, `viewProject`,
  `viewAsset`) per charm.md — open-ended navigation depth makes
  this fragile; a single screen would need to know every other
  screen's enum value to push it.

## Assumptions

- The shell does not need to host its own modal layer — **Why:**
  the existing `internal/tui/components/modal` package already
  implements focus stealing and z-layered compositing. Screens that
  need a modal use it directly; the shell only routes messages to
  the active screen.
- `RenderError` was unused after deleting the legacy flows —
  **Why:** the toast pipeline carries severity + text already
  styled via `notifications/render.go::renderNotification`; no
  caller asked for the multi-line error block. Reintroduce if a
  later screen actually needs it.

## shell package

Net new. The full surface is:

```go
// internal/tui/shell/screen.go
type Screen interface {
    Init() tea.Cmd
    Update(msg tea.Msg) (Screen, tea.Cmd)
    Body(width, height int) string
    Title() string
    StatusKeys() []key.Binding
}

type PushScreenMsg struct{ Screen Screen }
type PopScreenMsg struct{}
```

The root `Model` lives in `shell.go`, the global key map in
`keys.go`, the status-bar composer in `statusbar.go`, and the four
stubs (welcome, notifications, settings, info) in `welcome_stub.go`.
Stubs except `welcomeStub` pop on `esc` and will be replaced
wholesale by tasks 0023/0024.

## cmd/af/main.go

```go
// before
func main() {
    registryPath := flag.String("registry", registry.DefaultPath(), "path to profile registry")
    flag.Parse()
    if err := tui.Run(app.New(*registryPath)); err != nil {
        fmt.Fprintln(os.Stderr, err)
        os.Exit(1)
    }
}
```

```go
// after — build the dependency chain explicitly, then hand the
// shell to tea.NewProgram; the shell declares alt-screen on
// tea.View per Charm v2.
func main() {
    registryPath := flag.String("registry", registry.DefaultPath(), "path to profile registry")
    flag.Parse()

    svc := app.New(*registryPath)
    a := actions.New(svc)
    log := notifications.NewLog()

    if _, err := tea.NewProgram(shell.New(a, log)).Run(); err != nil {
        fmt.Fprintln(os.Stderr, err)
        os.Exit(1)
    }
}
```
