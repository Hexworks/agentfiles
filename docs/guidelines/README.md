# Guidelines

Guidelines define how the project should be developed and documented across
multiple changes. They are not architecture decisions themselves; instead they
describe the preferred way to work within the architecture that the ADRs and the
current codebase establish.

Use these files when you want to understand how to model the domain, how to
author assets, how to evolve the Go code, and how to preserve the project's
safety guarantees.
